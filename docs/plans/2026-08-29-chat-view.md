Scope: **frontend** (`packages/app`, `packages/shared`) + small e2e infra additions. Desktop only — mobile chat is a later PR; `MobileWorkbench` must keep compiling but gets no agent-session UI. Do not touch `crates/*` except nothing (backend is done; if you believe a backend change is required, STOP and write it in the report instead of doing it).

- **Design (authoritative)**: `docs/design/next-ia/Main.dc.html` (chat view + sidebar with status/unread/inbox), `States.dc.html` (status system rules — read its annotations carefully), `NewSession.dc.html` (new-session flow incl. auto-run + PROD), `Split.dc.html` (chat pane semantics — v1 exception below). ## Scope decisions for THIS PR

- Selecting an agent session shows the **ChatView full-area** on the right (like a zoomed terminal). Chat-inside-a-split-pane (Split.dc.html) and the Chat|Terminal mode switch (resume-into-tmux) are explicitly **out of scope** — leave no dead UI for them.
- Terminal behavior, mobile, and the `⌃B` terminal shortcuts must not regress.

## 1. Shared TS types (`packages/shared/src/contracts.ts`)

Mirror the Rust protocol additively: `AgentKind`, `AgentSessionStatus` (`starting|working|asked|idle|error|disconnected`), `AgentSessionInfo`, `AgentQuestionOption`, `AgentEvent` (discriminated union on `type`: `user_message|agent_message_chunk|thought_chunk|tool_call|tool_call_update|plan|question|question_resolved|turn_ended|error`), the three snapshot fields (`agent_sessions`, `agent_session_seen`, `MachineInfo.production`), and the five browser event variants. Check real wire casing against `crates/protocol/src/lib.rs` serde attributes.

## 2. Data layer (`packages/app/lib`)

- `api.ts`: `createAgentSession`, `promptAgentSession`, `answerAgentSession`, `cancelAgentSession`, `resumeAgentSession`, `destroyAgentSession`, `getAgentSessionEvents(machineId, id, fromSeq, limit)`, `putAgentSessionSeen(id, lastSeenSeq)` — follow the existing fetch helpers (device_id fields where the backend routes expect them; read the hub route handlers to get the request bodies right).
- `bootstrapState.ts`: snapshot fields + the five envelope events → state (`agentSessions: AgentSessionInfo[]`, `agentSessionSeen: Record<string, number>`). `agent_session_event` envelopes do NOT accumulate raw events in this store — they update `last_event_seq` on the session and are forwarded to the transcript store (below). Extend the existing tests.
- **Transcript store** — new `lib/agentTranscript.ts` (pure, vitest-covered): builds the renderable transcript from an ordered event stream. Rules: consecutive `agent_message_chunk` aggregate into one assistant message (closed by `turn_ended`, `user_message`, or any non-chunk block); same for `thought_chunk` into one collapsible thought block; `tool_call` creates a row that `tool_call_update` mutates (by `tool_call_id`); `question` becomes an ask-card marked resolved by `question_resolved`; `error` is a system row; `turn_ended` closes the turn. Must be incremental (append events without rebuilding) and support seeding from a backfill page + live continuation, including the overlap/dedup case (drop events with seq ≤ last applied).
- Per-session runtime store `lib/agentSessionFeed.ts`: on open → `getAgentSessionEvents(from_seq = 0…)` backfill (last 500), then apply live envelope events; expose to React via `useSyncExternalStore` or the pattern the codebase already uses for terminal previews (`terminalPreviewMuxReact.tsx` is prior art — follow its shape).

## 3. Sidebar integration

- `lib/sidebarTree.ts`: sections gain agent-session rows. Placement: an agent session with `workspace_group_id` joins that group's section; otherwise it joins the section whose group cwd equals its cwd, else a synthetic cwd-labelled section (same fallback style the terminal side already has). Row model gains `kind: "terminal" | "agent"`, `agentKind`, `status`, `unread` (`last_seen_seq < last_event_seq`, only meaningful when not the open session). Extend the existing vitest suite.
- Row rendering per `Main.dc.html` + `States.dc.html`: agent rows get a 2-letter agent badge (CL/CO/GR/KI) and a status dot — working = info blue, asked = amber diamond (ONLY amber use), idle = hollow gray ring, error = red, disconnected = dashed ring + dimmed, starting = pulsing gray. Unread = bold title + small solid dot. Terminal rows keep today's reachability dot; **terminal rows never show amber**.
- **Inbox banner**: persistent slim banner at the top of the tree, only when ≥1 session is `asked`: "N waiting on you · oldest Xm". Click expands a dropdown listing asked sessions (title + question first line); clicking one selects that session. No approve/answer-in-place in this PR (the card in ChatView handles answering). Hidden when zero.
- New-session entry: sidebar "＋" opens the **new-session dialog** (per `NewSession.dc.html`): agent picker (claude/codex/grok/kimi/terminal chips), machine list (reachable machines; a `production: true` machine shows a PROD tag + "auto-run off by default" note), cwd (machine bookmarks + free-text input), Auto-run toggle (default `!machine.production`). Terminal choice routes to the existing create-terminal flow with the chosen machine/cwd. Creating an agent session selects it on success. Disabled when not controller.

## 4. ChatView (`components/AgentChatView.web.tsx`)

Layout per `Main.dc.html` (tokens from `lib/colors` — match, don't invent):
- **Header**: agent badge + title, `machine · cwd` line, status pill, `auto-run` / `auto-run off` label, kill (✕ with ConfirmDialog), Resume button only when disconnected/error.
- **Stream**: scrollable column; user messages right-aligned-ish per design; assistant markdown-lite (monospace-friendly plain text with preserved newlines is fine — NO markdown lib dependency); thought blocks collapsed by default ("thinking…" toggle); tool-call rows collapsible (title + status icon: spinner/check/red ✕, expand shows `content` preformatted, scrolls in its own `overflow auto` box); ask-card: prompt + option buttons + "or reply below" hint, resolved state renders the chosen outcome dimmed; error rows; a subtle turn divider on `turn_ended`.
- **Autoscroll**: stick to bottom while at bottom; new content while scrolled up shows a "jump to latest" chip (see how terminal scrollback handles this if prior art exists; otherwise standard implementation).
- **Input**: textarea (Enter sends, Shift+Enter newline), Send button; while `working` the send affordance becomes Stop (calls cancel). Disabled with a "viewing — Take control" hint when the user is not the machine controller (same gating as terminal input; reuse the control-lease helpers). While `starting`: input enabled (backend queues) but show a subtle "starting…" note.
- **Answering**: option click → `answerAgentSession(request_id, option_id)`; typing a reply while an ask-card is open → send as `answer` with `text` (backend treats free-text as cancel-and-relay; read the backend REPORT deviation note and reflect the actual semantics — if free-text answers cancel the permission request, then only offer option buttons on permission-questions and route free text to `prompt` after the card resolves; verify against the fake agent and document what you did).
- **Read state**: while the session is open and the window focused, debounce (~1s) `putAgentSessionSeen(last_event_seq)`; apply inbound `agent_session_seen` events so other devices' reads clear local unread.
